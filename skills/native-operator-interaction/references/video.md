# Explaining through video

Use video when movement, timing or a sequence of actions materially explains the mechanism, or when the user requests it. A video is optional, not a required companion to an HTML report. Follow the same evidence and analogy rules as explanation.md.

## Capability and authority

Verify the current environment's recording, programmatic animation, encoding, speech and caption capabilities. A tool listed in a catalog or a working text model does not prove video generation is available. Never invent a rendered artifact from a storyboard.

Before paid generation, verify the actual route, price basis, requested duration/resolution and authorized budget. Do not silently switch to a paid provider, create accounts or send private material to an unapproved destination. A subscription is not evidence that generation is free. Use existing native authentication without transferring credentials to a worker.

Verify the live API schema, planned number of attempts and total cost uncertainty before spending. Check the chosen route's retention and content-use policy for the specific data; an available account does not establish zero retention or permission to process private faces, voices or documents. When external rendering is unavailable, inspect an already authorized local capture or programmatic-rendering route; otherwise deliver a storyboard clearly labelled as unrendered. Do not install or enable a fallback merely because it is mentioned here.

## Workflow

1. Define the audience, one understanding goal, language, approximate duration and sound mode. Make mobile labels readable.
2. Draft a storyboard: time, idea, visual change, narration if any, exact on-screen text, source and verification method.
3. Check facts and key frames before costly rendering. Use a short rough animatic if it resolves uncertainty about pace.
4. Choose actual screen capture for observed UI behaviour, programmatic graphics for exact numbers and relationships, and clearly labelled generated imagery only for permissible illustration. Never use generated footage as proof of an experiment or deployed system.
5. If narration exists, make it explain causes rather than simply reading all labels. Check pronunciation and timing; provide captions and a transcript. No unauthorised impersonation of a real person.
6. Maintain a readable equivalent without sound. Pause motion for important labels; avoid rapid flashing and provide an accessible written explanation.
7. Inspect the actual output, including beginning, end, transitions and each distinct segment; inspect a short video entirely. Check the sound separately when present. Confirm real playback in the intended format, not just a detected codec.

## Asynchronous generation

Retain safe job identifiers and poll the same job. A request timeout does not prove generation failed or no charge occurred. Check partial effects before a retry; use native idempotency when available. Do not publish temporary provider URLs as durable deliverables or accept unapproved callback destinations.

## Deliverables and status

Keep the verified video, editable project/storyboard and source references where authorized. Include transcript/captions for narration, or the full screen-text explanation for silent video. State which data version it explains, what is illustrative and what remains unverified. Rendering, reviewing, publishing and delivery are separate states.
